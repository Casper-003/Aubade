# 歌曲详情与联网资料

日期：2026-10-29。此阶段在 `Casper-003/song-details` 开发，接续此前已合入主分支的曲库与收藏；设计确认、实现和用户验收分别记录。

## 当前实现

- 曲库、收藏通过歌曲行进入详情，使用原生 Frame 历史；返回同一页面时复用内容与滚动位置。左侧封面、收藏与加入待播固定，右侧歌名、资料和歌词独立滚动。收藏与入队沿用已有操作和重复点歌确认。
- 最新[用户反馈](../pics/M02-details-and-lyrics-tags.feedback.png)明确详情页左右严格各半：移除整页最大宽度和 5:6 分栏，封面自身在左半区水平／垂直居中，操作按钮在其下方单独定位。最大边长暂用 560 单位，右侧资料 16 单位、歌词 18 单位，效果待用户复核。
- 本地读取歌名、艺人、专辑、唱片公司、年份、时长及内嵌歌词；缺字段隐藏，全部详情缺失才显示“无法获取歌曲详情”。自动检索中不提前显示“无法获取”或“暂无歌词”，后台活动继续集中在设置上方仪表。
- 图标入口提供“修改资料”“联网检索资料”。用户修正的歌名、艺人、专辑优先，显式清空艺人或专辑也会保留；后台扫描、联网更新、重启均不能覆盖这些修正，原媒体保持原样。保存失败时回退，弹窗保留错误提示。
- 打开详情即自动从文件名和已有标签生成搜索词，向 MusicBrainz／网易／Deezer 查询资料、向 LRCLIB／网易／酷狗查询缺失歌词。按歌名搜索，艺人放在本地辅助核对，检索不要求用户逐项发起。用户手选过的资料仍保留，地球图标只作手动纠正入口。
- 资料、歌词正文、原始时间轴及匹配状态一并缓存，重复打开不反复请求，断网仍能读缓存；无结果或歧义保留待处理，服务错误使用较短重试间隔，按接口要求处理 Retry-After。修正曲目身份会使旧歌词、旧自动状态和正在返回的旧结果失效。
- 在线封面按专辑获取，优先尝试 1200 像素版本，失败回退 500 像素图或灰色占位；本地音频可读取系统专辑缩略图。封面尚无应用自行管理的离线缓存。
- 没有本地视频的音频曲目，在打开详情并已有曲目身份、艺人和时长时，后台查询 B 站。当前保守核对名称、艺人、版本标记与时长，排除明显二创、相似标题、翻唱或不对应的现场版；通过时仅保存视频关联和可选查看链接，不展示候选确认列表。缺少可靠依据保留未匹配，网络失败不写成无 MV。

## 文件名自动识别

1. 保留原文件名，清理扩展名、明显序号与曲库编号、语言和画质标记，以及 Live、MTV、原MV原伴等检索后缀。保留英文标题本身的 Live、纯数字歌名等有效名称。
2. 从书名号、连字符、下划线等提取候选；兼容艺人在前或歌名在前，多艺人不固定按一段解释。每个文件最多生成四组搜索建议。
3. 先按歌名搜索，做简繁、大小写与标点归一化核对；利用已有艺人、文件名艺人线索以及歌词源的曲目资料辅助确认，不能只因歌名相似采用结果。
4. 候选内优先正式、较早的录音室发行；同名多艺人仍有歧义时不选第一条，保留给用户。原版未出现在服务返回范围内时，不能保证选中其首发专辑。
5. 歌词按歌名、艺人及可用时长核对，正文可独立阅读。Live 标记和近似时长只作时间轴基础兼容条件，不证明实际音频完全一致；未通过时不套用该时间轴。当前未进行演唱时间轴渲染。

## 快速滚动回归（2026-10-29）

- 标题双层粗细文字交叉淡化会产生轮廓错位重影，现仅用一层固定 Bold 字重文字；保留原有裁切、连续位移与缩放、主色以及工具按钮动画。
- 交替底色问题与 [WinUI #6635](https://github.com/microsoft/microsoft-ui-xaml/issues/6635) 的复现方式、症状一致。现由 SongRowSurface 内容根 Grid 直接绘制底色与即时悬停色，容器复用及内容初始化时设置绝对行索引，不依赖 ListViewItemPresenter 的背景状态缓存；复用时清除旧高亮。行绑定改为编译绑定（封面保留 ImageSource 动态绑定），同步数据上下文，保证操作对象不会串行。
- 旧 SyncRows 会把“一首歌从首位改名移到末尾”变成其余 1006 行逐一 Move。现保留最长有序子集，该情况只发一次 Move；纯删除也不再推动其后的所有行。新增 LastFilterMilliseconds / LastCollectionMoves 诊断值。元数据仅读取当前视口行，等待读取槽位期间离开视口的请求跳过，显式打开详情的读取保留。
- 自动控件回归通过：VESPER_RUNTIME_CHECK_PATH 启用隔离模拟数据，不初始化真实曲库、不读媒体、不联网。1007 行、24 次跨区 ChangeView、59 处 RenderTargetBitmap 实际背景像素、4 项悬停/复用状态检查通过；最大 47 个行容器，虚拟化有效。报告位于忽略目录 local-data/performance/overview-runtime.json。其程序化滚动和直接状态调用耗时不代表物理鼠标响应或交互帧率，也不替代视觉验收。
- 上轮 PID 11412 的 UI 排队峰值由启动时 213.44ms 增到 1447.25ms，确有使用期间长停顿；20 秒 dotnet-trace 采样区间处于等待，未复现操作，不能据此排除框架绘制耗时或把上述排序隐患认定为全部卡顿的唯一原因。新预览继续保留限长历史与长停顿上下文，供实际复现后对照。

## 快速跨行反馈修订（2026-10-29）

- 用户确认滑动卡顿已解决，本轮仅排查快速跨行响应。活动记录出现 200ms 以上排队延迟时，元数据读取为 0、重排移动为 0、上次排序约 3.49ms，不再把这段反馈迟钝归因于资料任务；采样仍主要停在原生 WinUI 边界，不能据此断言唯一内部原因。
- 歌曲行改为无悬停状态的 ContentPresenter 模板，目录管理保持原生模板。固定交替底色不随悬停更换，文字与按钮下方的圆角 Composition 图层只切换 Opacity，没有淡入淡出或尺寸/布局变化；共享高亮拥有者使进入新行时立即清除旧行，迟到的旧行退出不会清掉新行。
- 浅行悬停提亮、深行悬停压暗。深色主题为 43→56 / 34→22，浅色主题为 250→255 / 239→224（RGB 灰度）。图层颜色在主题实际变化时同步，未变化的系统颜色通知不再替换资源或遍历刷新行。
- 回归继续覆盖千行快滚与正常底色像素；另检查 Composition 图层状态、颜色、复用重置、唯一高亮拥有者及两种主题的明暗方向。RenderTargetBitmap 的普通背景像素检查不代表合成高亮像素或物理鼠标输入延迟已验证，实际手感仍由运行窗口复测。
- 本轮控件回归通过：1007 行、24 次跨区跳转、59 处正常底色像素、8 项图层/复用/拥有者/主题检查，最大 51 个行容器；1000 次直接高亮状态切换耗时 0.345ms。最后一项仅衡量程序调用与属性提交，不能换算成真实鼠标延迟或帧率；报告位于 local-data/performance/overview-hover-runtime.json。Debug x64 零警告、零错误。
