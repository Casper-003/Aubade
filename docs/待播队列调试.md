# 待播队列卡片

日期：2026-10-30。功能分支：`Casper-003/queue-cards`，基于已合入 PR #4 的 main（`be94193`）。旧 `Casper-003/queue-panel` 本地及远端分支已按用户要求删除。

## 当前实现

- 右侧队列与左缘开合边栏共用整体卡片，入口垂直居中，“<”展开、“>”收起并有旋转过渡；取消右上角关闭按钮。展开后数量只留标题右侧，收起时放在箭头下方。整根竖条均可点击，收起时悬停向左探出 4 单位。展开后内容右侧留出与左缘竖条相同的 34 单位空间。
- 开合保留约 220ms 的真实宽度动画：浏览卡片、原生勾边和圆角连续收窄，队列固定宽内容通过 Canvas 右锚和缓存裁剪显示，不再缩放卡片轮廓或补移动画。固定 96 字形再放大造成模糊的做法已撤回，标题按背景宽高使用实际 FontSize/LineHeight，展开比例为 1，滚动只缩小；相同值不重复提交。
- 浏览内容包在独立圆角裁剪内，内圆角 7、外框 8、内缩 1，背景不盖住浅勾边。悬停的 4 单位微动与完整展开分开：共享 Composition 标量同步两卡片轮廓、内容裁剪和箭头，右缘固定、可见间距保持 4；不改变页面、标题、歌曲行及按钮的布局，也不缩放文字/边框/圆角。静止后落到明确几何端点，离开、主题/尺寸变化和完整展开前恢复原生边框。参见[间距标注](../pics/M01-equal-card-gaps.feedback.png)。
- 微动期间以圆角几何绘制边框，描边固定 1、圆角固定 8，背景与描边按原生 Brush 的颜色/透明度分别处理。布局槽保持 34，透明点击区域覆盖最大 38，包含新增 4 单位；图标仅作合成位移。完整展开仍使用已认可的 220ms 真实宽度动画。
- [空白队列反馈](../pics/M03-empty-queue.feedback.png)根因是 Canvas 子卡片用 ElementName 绑定 ActualHeight，初始读到 0 后不能跟随实际高度更新。已移除该绑定，在 Host.SizeChanged 及布局落稳时显式同步卡片高度。微软明确说明 [ActualHeight 不支持这种绑定通知](https://learn.microsoft.com/en-us/windows/windows-app-sdk/api/winrt/microsoft.ui.xaml.frameworkelement.actualheight?view=windows-app-sdk-1.8)。旧检查仅验证外壳与已创建行，漏掉了卡片真实高度/祖先裁剪；现已补上整树绘制和命中验证。
- 公共导航内容容器透明且无描边；每张卡片共用 `ShellCardStyle` 各自画一圈相同的 1 单位浅勾边，不再有跨两卡的上/左公共线。内容常规宽度 400，收起外壳约 36（内部手柄区域 34 加外壳两侧细线），卡片间距 4、上下对齐；保留原有窗口外沿及窄窗口浏览区约 320 单位。
- 无浏览区遮挡层，展开时可继续点歌，追加歌曲保持展开及浏览位置；切换页面、左缘箭头或 Esc 收起。用户标注见[位置反馈](../pics/M03-card-outlines-and-toggle.feedback.png)。
- 当前歌曲固定在上方，待播列表独立滚动；没有当前歌曲时隐藏该区。真实演唱尚未接入，当前区在未来播放器设置当前歌曲后显示，不以测试歌曲冒充真实演唱。
- 独立条目 ID 支持同一歌曲重复入队；排序、右键插播、移除与恢复只作用于对应条目，保留正在演唱及暂停状态。
- 手柄采用应用内指针捕获，越过 4 单位阈值后整行随光标浮动，其他歌曲以约 140ms 过渡让位；列表投影实时预览顺序，Core 队列直到松手才提交一次，避免每个落点触发保存。Esc、失去捕获或有效区域外松手恢复原顺序；并发队列变化安全取消预览，不丢新歌曲。边缘滚动按实际时间限速，手柄仍支持上下方向键。
- 待播和当前行复用既有 SongRowSurface，独立管理悬停拥有者，插删/重排后更新交替底色，主题变化同步。待播滚动条仍位于 34 单位右留白中；曲库/收藏采用 16 单位整页右侧透明轨道，直接覆盖全宽页头主色背景，右缘与下部页面对齐；外置原生 ScrollBar 同步原 ScrollViewer，保留虚拟化及鼠标/键盘滚动。滚动或轨道悬停/拖动显示，停止约 1 秒后淡出。一页可放下时隐藏并禁止滚动，不再补尾部空白。未改既有跨行高亮延迟逻辑。
- 连续移除可在 5 秒内从最近一项逐条撤销；提示独立于队列卡片，收起后仍能撤销。加入后显示位置、音符飞入图标及接收动效，保持原开合与浏览位置。
- 不可用条目不隐藏；打开面板及之后每 5 秒在后台复核全部收录来源，灰显、标注并禁用插播，仍可排序及移除。
- 队列条目、顺序及未唱完的当前条目随本机曲库保存。重启时当前条目回到待播队首，保持空闲，面板默认收起。关闭窗口前等待保存，失败时保留窗口和队列并显示错误，可处理后重试。
- 真实播放、自动下一首及开始/返回演唱入口仍归 M04；本轮未接入替代播放按钮，也未处理原歌曲行的高亮迟钝。

## 用户检查

1. 用“<”展开，确认没有跨两张卡片的公共上/左边框，每张各自有相同浅线；箭头位于队列左缘中间，右上角无“×”，展开数量只在标题右侧、收起数量在箭头下方。
2. 重复加入同一首，确认位置提示与“再次加入”；分别拖动、右键插播，确认是对应条目移动。
3. 展开队列时继续从曲库加歌，确认第一次点击即可加入且队列保持展开；再切换收藏页，确认自动收起。连续移除与撤销后，重新展开仍保留浏览位置。
4. 用 Tab 聚焦行内控件，检查移除入口及手柄上下方向键；悬停超长标题时只滚动当前标题。
5. 将某首歌曲的全部有效来源暂时移开，确认待播条目仍保留并标注不可用；恢复来源后复核应恢复正常。
6. 关闭并重开软件，确认待播顺序及重复条目恢复，保持未开唱、队列收起；最后再确认系统浅/深色和窗口缩放。
7. 悬停收起的整根右侧竖条，确认短距探出；分别点顶部、底部及箭头附近，应均可开合。观察箭头转向、快速反向，以及窗口宽窄、曲库页头已收缩时的过渡。
8. 按住手柄让整行随光标移动，确认其他行连续让位；分别向上、向下、边缘自动滚动后松手，再用 Esc 或拖出列表取消。观察取消后原顺序恢复、没有隐藏行，滚动条不盖住行内按钮。

### 2026-10-30 排序手柄启动修正

以下为此前系统拖放启动修复记录；当前已由上方应用内实时整行拖动取代。

- 用户确认“按住手柄拖不起来”。旧手柄使用 Button 的默认点击/指针处理，并且拖动包只写入 `Properties` 元数据，未提供实际数据格式及移动意图；静态代码不能证明按钮处理是唯一原因。
- 改为可聚焦的非按钮手柄，在按下有效指针时显式调用 [StartDragAsync](https://learn.microsoft.com/en-us/windows/windows-app-sdk/api/winrt/microsoft.ui.xaml.uielement.startdragasync?view=windows-app-sdk-1.8)，保留键盘上下排序。`DragStarting` 写入 `Vesper.QueueEntry` 格式和对应条目 ID，并设置 `RequestedOperation=Move`，接收端依据格式判断。
- 取消/完成后清理拖动状态；启动失败显示可读提示。控件回归验证了格式、移动意图、条目 ID 及非按钮可聚焦手柄，但真实鼠标按住、向上/向下落位、拖到列表尾部和取消拖动仍需用户操作验收。

```powershell

```

本机预览可临时设置 `VESPER_PREVIEW_PAGE=曲库`、`VESPER_PREVIEW_QUEUE=1` 后启动输出目录的 EXE，直接显示待验收状态；这些环境变量不保存到用户配置，常规启动仍默认收起队列。

性能体验同时区分 Debug/Release 构建、是否附加 Visual Studio 调试器，以及首次冷启动和预热后的状态。当前微小悬停优化提供直接启动的 Release EXE，路径为 `src/Vesper.App/bin/x64/Release/net10.0-windows10.0.19041.0/win-x64/Vesper.App.exe`；直接运行 Debug EXE 也可能没有附加调试器，不能把两者混为一谈。单次重试变顺可能与预热有关，不作为调试配置是唯一原因的证据。
