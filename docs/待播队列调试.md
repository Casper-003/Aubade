# 待播队列卡片

日期：2026-10-30。功能分支：`Casper-003/queue-cards`，基于已合入 PR #4 的 main（`be94193`）。旧 `Casper-003/queue-panel` 本地及远端分支已按用户要求删除。

## 当前实现

- 右侧 36 单位边栏与队列内容共用一张整体卡片，收起只显示边栏。入口为垂直居中的“<”，展开后同位置改为“>”，保留数量和右上角关闭按钮。展开以约 220ms 的内容区宽度过渡占位，浏览卡片同步收窄。
- 左右卡片共用 `ShellCardStyle`，统一为原左侧较浅的勾边效果，右侧移除额外描边、ThemeShadow 和 Z 偏移；内部队列内容容器不再另画一层卡片。内容常规宽度 400、边栏 36，外壳间距 4，上下沿对齐，共用原有窗口外沿；窄窗口保留浏览卡片约 320 单位。
- 移除原来覆盖浏览区的透明关闭层，队列展开时浏览区可直接点歌，追加歌曲保持队列展开及浏览位置。切换页面仍收起队列，箭头、右上角关闭按钮及 Esc 同样可收起。
- 当前歌曲固定在上方，待播列表独立滚动；没有当前歌曲时隐藏该区。真实演唱尚未接入，当前区在未来播放器设置当前歌曲后显示，不以测试歌曲冒充真实演唱。
- 独立条目 ID 支持同一歌曲重复入队；排序、右键插播、移除与恢复只作用于对应条目，保留正在演唱及暂停状态。
- 手柄拖动有插入位置和边缘滚动，松到有效区域外取消；手柄聚焦时可用上下方向键排序。移除入口在悬停或键盘聚焦行时显示。
- 连续移除可在 5 秒内从最近一项逐条撤销；提示独立于队列卡片，收起后仍能撤销。加入后显示位置、音符飞入图标及接收动效，保持原开合与浏览位置。
- 不可用条目不隐藏；打开面板及之后每 5 秒在后台复核全部收录来源，灰显、标注并禁用插播，仍可排序及移除。
- 队列条目、顺序及未唱完的当前条目随本机曲库保存。重启时当前条目回到待播队首，保持空闲，面板默认收起。关闭窗口前等待保存，失败时保留窗口和队列并显示错误，可处理后重试。
- 真实播放、自动下一首及开始/返回演唱入口仍归 M04；本轮未接入替代播放按钮，也未处理原歌曲行的高亮迟钝。

## 验证

- 数据检查 138 项通过，新增队列检查覆盖独立重复条目、排序/插播不打断当前歌曲、原位撤销、跨启动恢复、未唱完歌曲回队首、损坏记录保护与保存失败后保留队列。
- Visual Studio 自带 MSBuild 的 Debug x64 构建通过，零警告零错误。
- 一体外壳修订后专项复核通过：22 次开合、144 次普通标题复位、72 次滚动标题启动/复位；共享浅色卡片样式、4 单位外壳间距、箭头垂直中心及左右方向、收起后的单边栏宽度和程序化追加歌曲保持展开均通过。报告在 `local-data/diagnostics/queue-unified-shell-regression.json`；实际点击加歌及视觉效果仍按下方清单人工验收。
- 常规界面验收只启动窗口供用户操作，不进行桌面自动点击或物理鼠标验收；本次闪退专项控件回归见下节。编译和数据检查不等于拖动体验、动画流畅度或视觉效果已验收。

### 2026-10-30 展开队列闪退修复

- 用户反馈点击列表图标闪退。Windows 记录为 WinUI stowed exception（`0xc000027b`），WER 签名包含无效参数 `80070057`。
- 诊断版本通过现有队列展开路径稳定复现：日志已越过 `Storyboard.Begin`，在首显行的 `ResetQueueTitle` 调用 `StopAnimation("Translation.X")` 前停止，未执行到调用后。首显标题此前并未启用或初始化 Translation 属性，不能无条件停止该动画。
- 修复为只跟踪并停止实际启动的滚动标题，普通标题复位不访问动画属性；启动标题及入队音符动画前先启用并初始化 Translation。标题卸载时清理已启动的动画。属性初始化依据[微软 XAML/Visual 互操作说明](https://blogs.windows.com/windowsdeveloper/2017/07/19/new-lights-propertyset-interop-xaml-visual-layer-interop-part-two/)。
- 这是针对本次原生闪退的专项控件回归，不改变常规人工界面验收约定。`VESPER_QUEUE_CHECK_PATH` 启用隔离数据，不初始化/保存真实曲库、不解码媒体；直接调用实际队列图标处理函数，覆盖普通标题首显/复用、超长标题启动后复位、当前歌曲保持暂停，以及打断开合动画。
- 专项回归通过：20 次开合、144 次普通标题复位、72 次滚动标题启动/复位，实际布局坐标的 4 单位间距及上下对齐检查通过，进程退出码 0。报告在忽略目录 `local-data/diagnostics/queue-regression-after-fix.json`；复现阶段记录在同目录 `queue-before-fix.log`，不入库。

## 用户检查

1. 在曲库加入至少三首歌曲，用边栏中间的“<”展开；确认边栏和队列为同一张卡片、左右边缘深浅一致，箭头原位变成“>”，最小窗口下空间仍可用。
2. 重复加入同一首，确认位置提示与“再次加入”；分别拖动、右键插播，确认是对应条目移动。
3. 展开队列时继续从曲库加歌，确认第一次点击即可加入且队列保持展开；再切换收藏页，确认自动收起。连续移除与撤销后，重新展开仍保留浏览位置。
4. 用 Tab 聚焦行内控件，检查移除入口及手柄上下方向键；悬停超长标题时只滚动当前标题。
5. 将某首歌曲的全部有效来源暂时移开，确认待播条目仍保留并标注不可用；恢复来源后复核应恢复正常。
6. 关闭并重开软件，确认待播顺序及重复条目恢复，保持未开唱、队列收起；最后再确认系统浅/深色和窗口缩放。

构建和数据检查：

```powershell
dotnet build Vesper.slnx -c Debug -p:Platform=x64
dotnet run --project tests/Vesper.Core.Checks/Vesper.Core.Checks.csproj -c Debug
```

本机预览可临时设置 `VESPER_PREVIEW_PAGE=曲库`、`VESPER_PREVIEW_QUEUE=1` 后启动输出目录的 EXE，直接显示待验收状态；这些环境变量不保存到用户配置，常规启动仍默认收起队列。
