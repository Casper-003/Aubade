# Vesper 产品模块划分

更新日期：2026-10-27  
用途：给团队和多端接力提供共同地图。按产品使用流程组织，不等于已经确定代码项目或左侧导航栏位。

模块范围为当前组织建议。这里引用的已确认内容来自用户明确决定；讨论中的设想和评审建议不自动成为需求。当前八块均未实现，后续只逐项讨论，不在一轮内全部定稿。

## 总览

| 编号 | 模块 | 负责什么 | 当前设计状态 |
| --- | --- | --- | --- |
| M01 | 主界面与首页导航 | 导航、推荐、首次使用、常驻的进入/返回演唱入口 | 布局与首页方向已确认；入口形态待定 |
| M02 | 本地曲库、搜索与详情 | 找歌、辨认歌曲与版本、收藏、曲目详情 | 本地曲库已确认；列表与详情交互讨论中 |
| M03 | 点歌队列与排播 | 添加、重复点歌、插播、拖动和排序模式 | 核心点歌排队目标已确认；具体规则讨论中 |
| M04 | 演唱画面与本场流程 | 单/双屏、全屏返回、切歌、队列结束及结束本场 | 显示模式与过渡方向已确认；结束行为讨论中 |
| M05 | 曲目预览 | 悬停轻预览、迷你播放器、进度和试听边界 | 讨论中 |
| M06 | 房间与手机点歌 | 局域网加入、成员身份、代点和操作权限 | 局域网网页方向已确认；身份权限讨论中 |
| M07 | 歌词体验 | 逐字/逐行显示、来源匹配、版本和偏移、MV 歌词选择 | 体验方向与优先评估路线已确认；显示细节待定 |
| M08 | 音频与演唱控制 | 人声/伴奏音量、返听、音效入口和音频模式选择 | 三种模式已确认；控制布局与具体效果范围待定 |

已确认、未实现和待验收是不同状态；不能仅因为一块已经画出草图就标为完成。

## M01 主界面与首页导航

- 范围：主界面三栏、功能导航、推荐区、空曲库引导，以及贯穿搜索/详情页的进入或返回演唱入口。
- 已确认：左侧导航、中央推荐、右侧队列默认收起；首页采用本地曲库推荐、最近唱过、常唱与收藏等方向；第一次使用有明确添加入口。近距离浏览和远距离演唱分别考虑字号与信息密度。
- 待讨论：顶部固定入口还是右下悬浮入口；无歌曲、待开始、正在演唱等状态分别显示什么文案。
- 可从一个小问题开始：已经有人在唱时，主界面上的“返回演唱”入口放在哪里、包含哪些信息？
- 协作者可交付：两张入口位置的低保真对照图；由后续讨论选择，不自行当作定稿。

## M02 本地曲库、搜索与详情

- 范围：曲目导入后的浏览与搜索、歌曲身份/版本辨认、收藏和详情信息。
- 已确认：先采用本地曲库；搜索支持歌名、歌手及拼音/首字母。B 站 MV 接入保留为后续候选。
- 待讨论：点击歌曲行/封面的行为，加入队列/收藏/预览按钮的呈现，以及歌手、作曲家、专辑信息的层级。按歌手区分同名曲目、联网补充详情等是本轮提案，尚待逐项确认。
- 可从一个小问题开始：歌曲行的哪些区域进入详情，哪些区域执行独立操作？
- 协作者可交付：10–15 条虚拟曲目样例，覆盖同名、不同版本、无封面和超长标题。

## M03 点歌队列与排播

- 范围：待播项目的添加、移除、插播、重复确认、拖动、轮唱/排序，以及当前与下一首的展示。
- 已确认：首个完整流程包含加入队列和切下一首；主界面的队列可以展开与收起。
- 待讨论：重复点歌提示、右键排到下一首、点歌顺序/一人一首/最新优先、拖动后是否进入手动排序，以及新加入歌曲的位置。演唱者/操作人的身份由 M06 定义，本模块使用这些身份安排队列。
- 可从一个小问题开始：同一首歌已经在队列时，再点一次应显示什么、确认后怎样加入？
- 协作者可交付：仅覆盖重复点歌的一页流程草图和几条验收场景。

## M04 演唱画面与本场流程

- 范围：进入、返回和退出演唱画面；单/双屏呈现；简易队列的舞台入口；一首歌和一场演唱的开始/结束。
- 已确认：单屏视频全屏；双屏一屏全屏视频、一屏保留主界面；可指定并记住视频屏幕；单屏采用展开过渡，双屏控制屏提供反馈、视频屏完成过渡；播放前准备资源与首帧。
- 待讨论：右侧边缘简易队列的呼出方式；自动续播、空队列 Logo 画面、返回主界面、结束本场与后续点歌的关系。这些本轮意见仍按讨论稿处理。
- 可从一个小问题开始：退出全屏回主界面时，当前演唱和按钮状态如何保持？
- 边界：队列的排序规则归 M03；这里只决定演唱画面怎么呈现相关控制。

## M05 曲目预览

- 范围：悬停封面的轻预览、主动打开的迷你播放器、拖动预览进度与声音控制。
- 已确认：尚无最终的预览行为规格。
- 待讨论：悬停 3 秒的触发、放大浮层、静音或有声、关闭方式、与正在演唱的歌曲如何共存。静音悬停、主动点击才试听是评审建议，尚未被用户确认。
- 可从一个小问题开始：演唱进行中，悬停预览允许呈现什么，哪些操作必须由用户主动点击？
- 协作者可交付：轻预览和主动预览两种状态草图，不扩展为完整播放器设计。

## M06 房间与手机点歌

- 范围：手机加入本场、昵称头像、成员角色、歌曲归属、代点提醒，以及谁能删除/排序/结束本场。
- 已确认：先采用局域网网页点歌，手机无需安装专用 App；电脑保留实际播放与队列状态。电脑热点是接入候选方式，公网中转暂不作为首版前提。
- 待讨论：昵称/头像是否必填；操作人和演唱者如何区分；谁可撤回代点；主人是否有额外管理权限；全员排序的操作提示。
- 可从一个小问题开始：小明替小红点歌时，这首歌在界面上属于谁，谁能移除？
- 边界：本模块定义身份和权限；M03 决定这些身份如何影响轮唱顺序，保持一份规则来源。

## M07 歌词体验

- 范围：歌词获取后的展示、逐字/逐行回退、版本选择、时间偏移，以及 MV 自带歌词与额外歌词的取舍。
- 已确认：优先评估 Lyricify Lyrics Helper；保留歌词版本选择、偏移调整与逐行回退。素材是否确有逐字数据、MV 是否与歌曲版本匹配，仍需验证。
- 待讨论：歌词的舞台位置、字号、当前/下一句信息、叠加开关，以及偏移调整如何让普通用户理解。
- 可从一个小问题开始：MV 已经带歌词时，额外歌词默认如何显示、用户如何切换？
- 协作者可交付：远距离观看的歌词排版草图，覆盖短句、长句与无逐字数据的场景。

## M08 音频与演唱控制

- 范围：人声和伴奏控制、返听与音效的用户入口、模式选择、保存及状态提示。
- 已确认：共享低延迟、独占、兼容共享三种 WASAPI 模式可由用户切换；目标支持普通 USB 麦克风和板载声卡，不把额外专业设备或第三方驱动作为使用前提。
- 待讨论：主界面和演唱画面各保留哪些常用控制、哪些放入设置；音效具体范围与默认值。设备兼容性和延迟另行实测，不在交互讨论中做性能保证。
- 可从一个小问题开始：演唱中最需要直接调节哪两个或三个控制，入口放在哪里？
- 边界：此处记录用户看到的控制与状态；底层音频引擎的工程验证独立安排。

## 共用部分与分工边界

视觉规范、设置保存、资源、测试和文档贯穿各模块，初期不额外变成一组复杂产品模块。设置页可以提供各模块的入口，但行为规则留在所属模块说明中。

参考界面、草图和样例数据是讨论材料。完成一个材料任务不等于确认其方案；确认设计也不等于已经实现或验收。

每次从某模块里选择一个小问题。确定后按 [协作指南](协作指南.md) 的模板记录，并更新 [项目记忆](../Vesper_项目记忆.md) 的重要共识与索引。没有必要立即创建八份空设计文档或同时启动八条开发任务。
