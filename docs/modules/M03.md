# M03 点歌队列与排播

更新：2026-10-28。电脑端主要队列交互及本轮不可用歌曲复核已确认；首版不做手机点歌，手机端预设及“一人一首”等已确认设计保留到后续版本。尚未实现或验收。

## 已确认

- 首个完整流程包含找到本地歌曲、加入队列、播放和切下一首。
- 主界面的右侧队列默认隐藏，可展开/收起。

### 电脑端普通入队

- 电脑端当前由一人集中点歌，普通点歌默认按点歌先后排播，先点先唱。
- 普通加入操作将新歌曲追加到待播队尾，保留已有待播条目的顺序，当前歌曲继续演唱。
- 例如 A 正在演唱、待播顺序为 B、C，再普通加入 D 后，待播顺序变为 B、C、D。

确认日期：2026-10-28。理由为让普通点歌的先后顺序可预期，并在添加歌曲时保留当前演唱过程。以上为设计确认，尚未实现或验收。

### 重复点歌

- 同一演唱版本已在待播列表中，再次点击加入时，提示已有条目的位置。例如：“这首歌已在待播列表第 3 位，仍要再加入一次吗？”
- 提供“取消”和“再次加入”两个选择；取消时队列保持原样。
- 选择“再次加入”后，在队尾新增一条，原有条目保持原位。

确认日期：2026-10-28。理由为让用户知晓已存在的待播条目，同时保留再次演唱同一版本的选择，并避免改变原有条目的位置。以上为设计确认，尚未实现或验收。

### 正在演唱时的队列插播

- 电脑端可在待播歌曲上右键选择“插播”，将选中的条目移动到待播第一位，其余条目保留原有相对顺序。
- 当前歌曲继续演唱，唱完后播放被插播的歌曲。例如 A 正在演唱、待播顺序为 B、C、D，对 D 执行插播后，待播顺序变为 D、B、C。

确认日期：2026-10-28。理由为让“插播”明确表示下一首演唱，并保留当前歌曲的完整演唱过程。以上为设计确认，尚未实现或验收。

### 电脑端拖动排序

- 每首待播歌曲右侧提供拖动手柄，用于上下调整待播顺序。
- 松手后立即按调整后的新顺序排播。
- 正在演唱的歌曲不参与拖动，当前演唱继续。
- 手动调整顺序后，普通新点的歌曲仍追加到待播队尾。

确认日期：2026-10-28。理由为提供明确的手动排序入口，让用户主动调整待播顺序，同时保留当前演唱及新点歌曲的入队规则。以上为设计确认，尚未实现或验收。

### 电脑端移除待播歌曲

- 歌曲行右侧提供移除按钮，光标悬停该行时显示。
- 点击后立即将该条目从待播列表移除。
- 移除后短暂显示“已移除 · 撤销”提示；点击“撤销”可将条目恢复到原位置。

确认日期：2026-10-28。理由为保持队列操作简洁，并提供误操作后的恢复入口。以上为设计确认，尚未实现或验收。

### 已入队歌曲中途不可用

- 已加入待播的歌曲因文件移动、删除或硬盘断开而无法访问时，先依据 [M02](M02.md) 的全部已收录来源规则判断，只有已无有效来源时才视为不可用。
- 检测到不可用时，待播条目灰显并标注“文件不可用”；浏览列表的“隐藏不可用歌曲”选项不隐藏该待播条目。
- 轮到该歌曲时，自动跳过并将该条目移出待播，短暂提示后尝试下一首。
- 后续待播歌曲均不可用时，停止推进，提示“没有可播放的待播歌曲”。具体等待画面归 M04。

确认日期：2026-10-28。理由为明确告知已点歌曲的失效状态，并在轮到不可用条目时继续尝试后续歌曲。以上为设计确认，尚未实现或验收。

### 手机端排列预设（首版不实现）

- 首版不包含手机点歌及其排列预设；以下已确认设计作为后续版本方案保留。范围确认日期：2026-10-28。

- 手机点歌时，待播列表提供“一人一首”“顺序”“逆序”三种预设排列模式。
- 三种预设作为持续生效的模式：切换模式时重新排列当前待播队列，后续新点的歌曲也自动按当前模式安排。
- 模式切换与自动排列只调整待播队列，正在演唱的歌曲继续播放。例如选择“一人一首”后，后来新点的歌曲也自动加入轮唱安排；基本规则见下节。
- “顺序”“逆序”的具体排序定义及各模式与插播、重复追加、手动拖动的关系仍待逐项确认，留到手机点歌阶段继续讨论；模式切换权限归 [M06](M06.md)。

确认日期：2026-10-28。三种预设的提供与名称按用户明确要求确认；持续生效、切换时整理待播队列及保留当前演唱过程已确认，理由为让后续点歌持续沿用用户选择的排列方式。具体排序规则仍在讨论。以上为设计记录，尚未实现或验收。

#### 一人一首：手机点歌阶段实现

- 按实际演唱者轮流，每轮每人一首。
- 每个人名下的歌曲按点歌时间先后排列。
- 没有待播歌曲的人跳过。例如小明有三首、小红有两首，两人轮流时可排为明1、红1、明2、红2、明3；初始轮次尚待确认。
- 当前电脑端由一人集中点歌，不启用“一人一首”模式；该模式留到手机点歌阶段实现，其他轮唱边界也在该阶段继续讨论。

确认日期：2026-10-28。基本轮唱规则已确认；用户明确将实现范围安排在手机点歌阶段，理由为当前电脑端由一人集中操作点歌。以上为设计确认与阶段范围安排，尚未实现或验收。
