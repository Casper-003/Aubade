# M04 演唱画面与本场流程

更新：2026-10-28。演唱与选歌切换、暂停、续播及退出规则已确认，仍有流程边界与视觉细节待讨论；手机点歌首版暂缓；尚未实现、尚未验收。

## 已确认

- 进入卡拉 OK 时视频全屏；目前取消双显示器方案，不再保留一屏演唱、一屏主界面及指定、记住视频屏幕的要求（2026-10-28，当前协作者确认）。
- 提前准备播放资源与首帧，进入演唱时展开到全屏。
- 常规切歌采用轻量反馈；具体动效节奏仍需原型验证。

### 演唱与选歌的切换（2026-10-28，当前协作者确认）

- 场景：演唱过程中，用户需要返回选歌界面。
- 常态全屏显示演唱画面；取消同屏分屏方案，不再保留 MV 与选歌界面左右 2:1 分区的要求。
- 选歌时切回 [M01](M01.md) 定义的主界面：当前歌曲原本正在播放时继续播放、声音不中断；原本已暂停时保持暂停（2026-10-28，当前协作者确认）。
- 主界面顶部演唱入口沿用 M01 的高斯模糊 MV 状态；点击该入口返回当前歌曲的全屏演唱画面，保留播放或暂停状态，歌曲不重新开始，也不因界面切换而自动恢复播放。
- 理由：统一沿用主界面选歌与顶部返回演唱入口，避免两套选歌布局并存。
- 验收依据：选歌时显示完整主界面，原本播放的歌曲声音持续，原本暂停的歌曲保持暂停；点击顶部 MV 入口返回全屏时保持当前进度与播放或暂停状态，不出现同屏选歌分屏。

### 暂停与继续演唱（2026-10-28，当前协作者确认）

- 场景：用户主动暂停当前演唱。
- MV 停在当前帧，声音暂停，显示明显的“继续演唱”按钮；暂停期间该按钮持续显示，不因无操作而隐藏（2026-10-28，当前协作者确认）。
- 点击“继续演唱”后，从暂停位置继续播放，自动收起操作界面，恢复 MV 与歌词的全屏演唱画面（2026-10-28，当前协作者确认）。
- 已暂停时返回主界面选歌，及随后通过顶部 MV 入口回到演唱画面，均保持暂停；由用户点击“继续演唱”才恢复播放（2026-10-28，当前协作者确认）。
- 理由：明确表达暂停状态，并让用户一次操作即可继续当前歌曲、回到全屏演唱。
- 验收依据：暂停时画面停止、声音暂停，即使无操作也保留“继续演唱”按钮；往返选歌与演唱画面时仍保持暂停；点击“继续演唱”后从暂停位置继续，操作界面收起，MV 与歌词恢复全屏。
- 取消分屏后，暂停时保持全屏演唱画面及暂停控件，不进入分屏布局。

### 全屏演唱控件的呼出（2026-10-28，当前协作者确认）

- 场景：全屏演唱时，用户需要返回选歌、暂停或退出本场。
- 移动鼠标或轻触演唱画面时，显示底部控制栏，其中提供暂停按钮；播放期间连续 3 秒无操作后自动隐藏控制栏，暂停期间保持显示（2026-10-28，当前协作者确认）。
- “返回选歌”入口位于底部控制栏左侧，随整栏一起显示或隐藏；点击后切回 M01 主界面，原本正在播放的歌曲继续播放、声音不中断（2026-10-28，当前协作者确认）。
- “退出本场”入口位于底部控制栏最右侧，与暂停按钮保持间隔；随控制栏一起显示或隐藏，沿用播放期间自动隐藏、暂停期间保持显示的规则（2026-10-28，当前协作者确认）。
- 理由：让选歌、暂停与退出入口容易找到，同时减少控制栏对演唱画面的遮挡，并区分返回选歌与退出本场。
- 验收依据：移动鼠标或轻触画面可呼出底部控制栏及暂停按钮；左侧“返回选歌”可切回主界面且不打断正在播放的歌曲；“退出本场”位于最右侧，与暂停按钮有间隔。播放期间连续 3 秒无操作后整栏自动隐藏，暂停期间不自动隐藏。
- 待验证：通过原型体验验证 3 秒等待时长是否合适；当前设计值为 3 秒，尚未实现或验收。

### 自然唱完后的续播（2026-10-28，当前协作者确认）

- 场景：全屏演唱中，当前歌曲自然唱完，待播队列仍有歌曲。
- 自动播放队列中的下一首，保持全屏演唱，无需逐首手动确认。
- 理由：保持演唱流程连贯，减少歌曲之间的操作。
- 验收依据：当前歌曲自然结束且队列非空时，自动开始下一首，画面保持全屏，不出现逐首确认步骤。
- 队列全部唱完后的等待画面暂选下文“霓虹舞台”方向；最终视觉、具体操作及结束本场行为仍待确认。

### 队列播完后重新点歌（2026-10-28，当前协作者确认）

- 场景：本场尚未结束，当前歌曲与待播队列均已唱完，随后又有歌曲加入队列。
- 新歌加入后保持等待，由用户手动触发“开始演唱”，不因队列从空变为非空而自动播放。
- 手动开始后，从当前队列的第一首开始演唱；后续自然唱完且队列仍有歌曲时，沿用自动续播规则，无需逐首确认。
- 理由：将重新开唱的时机交给用户，允许先准备、点歌，再开始演唱。
- 主界面的开始入口沿用 M01 的彩色 Logo 及无文字规则；这里的“开始演唱”指操作含义，等待画面中的入口呈现仍待设计。
- 验收依据：队列播完后再加入歌曲时不自动开播；用户手动开始后播放队列第一首，并可按已有规则自动续播后续歌曲。

### 退出本场与返回主界面（2026-10-28，当前协作者确认）

- 场景：用户从本场等待画面，或在演唱途中选择“退出本场”。
- 退出本场后回到主界面。
- 退出时保留尚未演唱的待播歌曲及其顺序，方便稍后手动开始；队列规则见 [M03](M03.md)（2026-10-28，当前协作者确认）。
- 演唱中退出时停止当前播放，当前歌曲保留在待播队首；下次手动开始演唱时从头播放（2026-10-28，当前协作者确认）。此规则适用于退出本场，暂停后继续仍从暂停位置播放。
- 演唱中点击“退出本场”时先二次确认，提示“将停止当前歌曲，下次从头播放；待播队列保留。”，提供“取消”和“退出本场”两个按钮（2026-10-28，当前协作者确认）。
- 当前歌曲正在播放时，退出确认弹窗出现后 MV 与声音继续播放，不自动暂停；只有确认退出后才停止（2026-10-28，当前协作者确认）。
- 只有确认“退出本场”后才执行上述退出行为；点击“取消”不结束本场，也不触发歌曲回到待播队首或重置播放进度。
- 手机点歌及相关房间功能首版暂缓；此前确认的保留房间和手机连接、单独关闭房间等规则留作后续版本设计，不作为首版要求，见 [M06](M06.md#退出本场与房间生命周期2026-10-28当前协作者确认)。
- 理由：退出演唱画面后，仍可方便地稍后继续点歌与演唱。
- 首版验收依据：演唱中退出时先显示上述确认提示与两个按钮，弹窗期间原本正在播放的 MV 与声音继续；取消后仍保留本场。确认退出后显示主界面，原待播歌曲与相对顺序保持不变；若有未唱完的当前歌曲，播放停止，该歌曲保留在队首，下次手动开始时从头播放。手机房间与连接相关行为留待后续版本验收。
