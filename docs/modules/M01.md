# M01 主界面与首页导航

更新：2026-10-29。主窗口外壳已按本轮确认规则重新实现并实际启动；完整首页内容仍未接入，用户体验验收尚未完成，最小窗口宽度数值待原型验证。

## 已确认

- 左侧功能栏竖向排列，可折叠、展开；中央为首页内容，右侧队列默认收起，可展开/收起。
- 软件左上角仅设置后退控件，独立于左侧竖向功能列表。2026-10-29 用户明确取消前进键及对应逻辑。
- 后退返回已浏览页面时，保留并恢复该页面之前的搜索词和滚动位置。
- 浏览与远距离演唱分别考虑字号和信息密度。

### 整体视觉方向（2026-10-28，Casper-003 确认）

- 全部继续采用 WinUI 3 与 Windows Fluent 视觉，不采用 MD3，不迁移 Flutter。用户本次更正取代此前的 MD3 方向。
- 保留 M01–M08 中已确认的要求和用户草图，废弃助手此前的功能原型方案，重新设计、实现；旧原型不作为视觉或交互依据。
- 设计与实现严格依据已确认规则；未确定的内容先向用户询问，不能自行添加交互、品牌文案或替换已确认布局，也不能擅自缩减要求。
- 具体主题、颜色、字体、形状、组件状态与动效中尚未确定的事项，逐项讨论后再实现；已确认事项不重复确认。

- 理由：用户明确选择跟随系统。

### 后退的浏览历史

- 仅记录页面之间的跳转：通过左侧导航进入其他页面，以及进入歌曲详情、艺人详情，均计入浏览历史。
- 展开或收起队列、打开或关闭弹窗，以及进入或返回演唱，不计入这套浏览历史。
- 例如从首页进入艺人详情，再进入歌曲详情，后退时依次返回艺人详情、首页，并恢复各页面之前的搜索词和滚动位置；中途展开队列不会增加一次后退。
- 后退时移除当前这一步历史，返回上一页面；随后打开新页面时，沿剩余路线继续记录。例如首页 → 艺人 A → 歌曲 B，后退回艺人 A 后打开歌曲 C，历史变为首页 → 艺人 A → 歌曲 C；从歌曲 C 后退仍返回艺人 A，不保留通往歌曲 B 的前进记录。
- 页面历史范围于 2026-10-28 确认；2026-10-29 用户取消前进，保留后退找回浏览位置的行为。搜索词和滚动位置恢复仍为设计要求，当前空页面外壳尚未实现。

### 顶部演唱入口

- 将 MV 预览、开始演唱和返回演唱合为一个顶部按钮，以扣除左侧导航栏后的内容区域居中；导航折叠、展开时随内容区域变化调整位置。此居中基准于 2026-10-29 由 Casper-003 确认。
- 没有正在演唱的歌曲且待播队列为空时，显示灰色 Logo，不可点击。
- 待播队列有歌曲且尚未开始演唱时，显示彩色 Logo；点击后按钮通过拉伸放大、展开的动画进入 KTV 模式。具体演唱呈现归 M04，目前双显示器方案已取消。
- 演唱中切回主界面选歌时，该区域显示当前 MV 的实时高斯模糊画面；点击即可返回演唱画面。
- 当前歌曲已暂停时，点击顶部 MV 入口仅返回演唱画面，仍保持暂停；用户随后点击“继续演唱”才恢复播放，具体状态规则见 [M04](M04.md)。确认日期：2026-10-28。
- 正在唱最后一首时，即使待播队列为空，也继续显示当前 MV，并保留返回演唱的入口。
- 三种状态均不配文字，保持整体简洁；不采用常驻“尚未点歌”“开始演唱”“返回演唱”等状态文案的建议。
- 草图中的专辑封面仅作为 MV 的占位素材，实际使用当前 MV。

### 首页内容

- 整体大方、简洁，保留充分留白。
- 首页按歌手或乐队/组合分类的大封面、推荐、收藏组织内容。
- 每个内容区采用一个标题、一行封面的布局；推荐与收藏的封面比歌手或乐队/组合分类的封面小一些。
- 歌曲封面点击后进入详情页，详情布局归 M02。
- 首页歌手或乐队/组合分类的大封面点击后，统一进入对应的艺人详情页，与歌曲列表中点击艺人名字的去向一致。确认日期：2026-10-28；理由为保持同一艺人在不同入口的浏览体验一致。艺人页内容与具体交互归 M02。
- 首页艺人卡片遵循外部艺人卡片优先显示 Logo 的规则：有可用 Logo 时优先使用 Logo；没有 Logo 时改用艺人照片，个人歌手用头像，乐队或组合用合照；照片也没有时，使用下文已确认的名称占位封面。确认日期：2026-10-28；理由为优先以 Logo 作为卡片的识别形象，并在缺少 Logo 或照片时保持可辨认的入口。乐队在艺人详情页顶部显示合照，与外部卡片分别处理，详见 [M02](M02.md)。
- 一行内容过多时采用横向列表，仅通过点击左右交互按钮浏览，不使用鼠标滚轮进行横向切换。
- 每个分类的封面始终保持一行；多个内容区使整页内容超过窗口高度时，使用鼠标滚轮纵向浏览整个页面。
- 窗口缩窄时保持封面大小，优先减少每行同时可见的封面数量，其余内容通过左右按钮浏览，不换行；维持歌手或组合大封面、推荐与收藏较小封面的层次。确认日期：2026-10-28；理由为保留封面的辨识度和大小层次。
- 收藏为空时不显示首页的收藏栏。
- 歌手或组合区、推荐区也采用同一空内容规则：没有可展示内容时隐藏整个区块，包括标题和占用的空间；首页仅排列其余有内容的区块。首次启动且曲库为空时，仍按既定规则显示导入曲库栏。确认日期：2026-10-28；理由为与收藏栏保持一致，避免空区块占用首页空间。
- 有内容但缺少封面图片时，保留卡片的位置、大小和点击入口，使用统一风格的占位封面，在其中显示对应艺人名或歌名；例如艺人没有照片时，仍保留带艺人名的大封面卡片，点击进入艺人详情。确认日期：2026-10-28；理由为保持首页布局稳定，并允许辨认和进入对应内容。
- 首次启动且曲库为空时，首页额外显示导入曲库栏；点击后选择歌曲目录。后续本地 MV 库管理在左侧导航的曲库页进行。
- 首版推荐区从当前可用的本地歌曲中随机挑选一组，点击封面仍进入歌曲详情页。确认日期：2026-10-28；理由为提供随意浏览、找歌唱的入口，刚导入曲库且没有演唱记录时也能展示推荐。
- 每次启动生成一组推荐，同一次运行中保持稳定；进入详情页或切换页面后返回首页，仍保留原组；下次启动再换一组。如果启动时曲库为空，就在导入歌曲后首次生成。确认日期：2026-10-28；理由为返回首页时能找回刚才浏览的推荐，并在下次启动时提供新一组歌曲。

### 推荐歌曲中途不可用

- 推荐歌曲因目录移除、文件失效或硬盘断开而失去全部有效收录来源时，按 [M02](M02.md) 的不可用歌曲规则处理；同一次运行中的原推荐组继续保留。
- “隐藏不可用歌曲”默认开启：隐藏失效歌曲的推荐卡片，其余歌曲保持原有顺序，不重新抽取或补入其他歌曲。
- 用户关闭“隐藏不可用歌曲”后，保留失效卡片并灰显，标注“文件不可用”；仍可进入详情页，禁用预览及加入待播。
- 文件恢复可用并刷新曲库后，重新显示原卡片，保留其在原推荐组中的顺序。
- 原推荐组的全部卡片均被隐藏时，隐藏整个推荐区，包括标题和占用的空间，沿用首页空内容规则。

确认日期：2026-10-28。理由为让推荐区遵循统一的不可用歌曲显示规则，同时保留本次运行的推荐组和浏览顺序，避免因文件暂时不可用而更换推荐。以上为设计确认，尚未实现或验收。

### 右侧队列入口

- 草图中的右侧为队列收起状态，点击展开入口后，队列从右侧滑出。
- 展开后采用类似 Spotify 的卡片式设计。
- 队列以覆盖层形式显示在页面内容上方，并通过阴影表达层级。
- 点击队列面板外部时收起队列；面板内同时保留明确的关闭按钮，点击后同样收起队列。
- 收起时显示待播歌曲数量；队列内部操作和排播规则归 M03。

除单独标注日期的事项外，上述设计确认日期：2026-10-27。主要理由为保持界面简洁、首页留白，以及将开始与返回演唱集中在同一位置。

## 左侧竖向导航

左侧导航的入口、用途及从上到下的顺序按下表确认；设置单独固定在底部。后退控件位于软件左上角，不属于此竖向列表。创作本轮仅确认入口和编辑已录制演唱作品的用途，具体编辑功能留到对应模块讨论。

- 导航展开时，导航项采用图标加常驻文字的呈现方式。确认日期：2026-10-29，Casper-003 确认；理由为用户明确选择图标加文字。
- 左侧导航支持折叠、展开。折叠后保留仅图标的窄栏，各导航入口仍可直接切换页面；展开时显示图标加常驻文字。折叠为窄栏于 2026-10-29 由 Casper-003 确认。
- 折叠、展开会改变主内容区域及顶部演唱入口的位置，演唱入口按上述内容区域居中规则调整。起始宽度确认为展开 220、折叠 56 个界面单位（100% 缩放下对应像素），用于实际运行窗口的首轮核对；这些尺寸可在用户查看后调整，不视为最终验收参数。确认日期：2026-10-29，Casper-003 确认。
- 折叠／展开按钮位于左侧导航顶部、首页入口上方；展开和折叠时都保留在同一位置。确认日期：2026-10-29，Casper-003 确认；理由为用户同意该入口安排。设计已确认，尚未实现或验收。
- 首次启动时导航默认展开；之后记住用户上次的展开／折叠状态，下次启动恢复该状态。确认日期：2026-10-29，Casper-003 确认；理由为用户同意保留上次的导航状态。设计已确认，尚未实现或验收。
