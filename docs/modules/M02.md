# M02 本地曲库、搜索与详情

更新：2026-10-28。主要交互设计已确认，整体复核的边界规则仍待补齐；尚未实现或验收，具体视觉参数仍待原型验证。

## 已确认

- 首版以本地歌曲与 MV 为基础，支持歌名、歌手及拼音/首字母搜索。
- B 站 MV 接入保留为后续候选，尚未验证完整接入能力或纳入首版。
- 点击歌曲封面进入歌曲详情页。确认日期：2026-10-27。

### 详情页操作按钮

- 首版不支持自建歌单，保留收藏；原草图中“加入歌单”的目标明确为加入待播列表。
- 专辑封面下方左侧为收藏按钮，再次点击可取消收藏；右侧为加入待播按钮。
- 操作按钮常态使用图标，不常驻显示文字；光标悬停在加入待播按钮上时，显示提示“加入待播”。具体图标样式尚未选定。
- 点击加入待播时，以一个音符飞向右侧队列图标的动画反馈，队列图标配合接收动效。队列收起后，图标位于右侧保留的小条区域；加入后的排播规则归 M03。
- 预览入口移到专辑封面上的悬浮播放图标，点击后呼出预览控件；预览行为、控件外观与弹出方式归 M05。

确认日期：2026-10-28。理由为保持按钮简洁，以悬停提示说明加入待播的用途，并通过动效表达歌曲加入队列的去向。本节为设计确认，尚未实现或验收。

### 详情页信息与滚动

- 详情信息排版干净简练，展示歌手、专辑、唱片公司与发行年份；资料允许从本地和联网获取。
- 部分字段缺失时，保留已知信息，隐藏缺失字段；仅在全部详情资料都无法获取时，显示“无法获取歌曲详情”。此规则针对详情信息区，不将缺少某个字段视为整块资料获取失败。
- 专辑封面及下方按钮固定在详情页左侧中间，不随滚轮向下滚动。
- 右侧歌词可向下延伸；向下滚动时，上方基本详情信息可滚出可视区域，继续浏览歌词。

确认日期：2026-10-28。字段、资料来源和滚动方式沿用用户明确给出的方案；本轮补充确认部分资料缺失的处理。理由为保留可用资料，并在浏览歌词时保持封面和操作入口可用。以上为设计确认，尚未实现或验收。

### 同名歌曲、版本与画质

- 同名歌曲的不同歌手分开列出，以演唱者信息区分。
- 同一歌手的不同版本集中展示一项，收起时优先展示原版 MV；不将不同版本的画质高低作为原版优先规则的替代。
- 没有原版 MV 时，收起状态展示最早加入曲库的可用版本，避免后续新增其他版本时频繁变换代表项；同一版本内部仍默认采用最高画质。
- 分组收起时，以展开下箭头替代该项的收藏与加入待播按钮；展开后，每个版本的子项具有完整的栏位及操作控件。
- 展开后的子项明确显示版本名称，如“原版 MV”“现场版”“伴奏版”，作为歌名旁的辨认文字；画质仍按单个清晰度标签呈现。
- 版本列表以比主列表略窄的弹出列表呈现，避免影响其余歌曲的显示；点击其他部位自动收回，弹出与收回均有动画。
- 同一个演唱版本有不同画质时，从已收录且可访问的文件中默认采用最高画质，合并为一个 MV 项。每个 MV 仅显示当前采用的一个画质标签，不显示其他画质档位或额外的“多种画质”标签。

确认日期：2026-10-28。分组、代表版本及子项版本名称已确认；画质呈现按用户最新要求，仅显示最高可用画质对应的单个标签。理由为减少重复行与标签、保持代表项稳定，同时让不同演唱版本易于辨认。以上为设计确认，尚未实现或验收。

### 搜索基本行为

- 输入时实时搜索；回车表示关键词输入完毕。
- 支持按歌名、艺人和专辑三种搜索模式。
- 无论使用哪种搜索模式，匹配到的最优专辑和艺人放在第一行，下方为歌曲搜索结果；结果按匹配度排序。
- 搜索栏为空时不显示结果；没有结果时显示“无匹配”。
- 首版不增加额外搜索筛选面板，保留三种搜索模式、匹配度排序和多版本展开选择。只看现场版、伴奏版等额外筛选需求留待实际使用后再评估，不纳入首版已确认范围。

确认日期：2026-10-28。实时搜索、搜索模式及空状态沿用用户明确给出的方案；本轮确认首版不增加额外筛选，理由为先保持搜索界面简洁，按实际需求再评估扩展。以上为设计确认，尚未实现或验收。

### 艺人与专辑页入口

- 点击搜索结果第一行的艺人卡片，进入对应艺人详情页，与首页歌手/组合封面、歌曲列表中的艺人名字保持相同去向。
- 点击搜索结果第一行的专辑卡片，进入对应专辑详情页；下方展示该专辑在本地曲库中已有的歌曲。

确认日期：2026-10-28。理由为保持同类入口的去向一致，并使专辑页的歌曲范围符合本地曲库优先的方向。以上为设计确认，尚未实现或验收。

- 歌曲列表上移，在精简标题栏下方继续滚动，获得更多展示空间，同时保留当前艺人或专辑的识别信息。

- 艺人和专辑的 pagedown 草图表达同一页面滚动后的状态，具体过渡动效参数尚待原型验证。

确认日期：2026-10-28。理由为在浏览歌曲列表时保留页面身份，并将更多空间留给歌曲。以上为设计确认，尚未实现或验收。

### 曲库目录管理

- 支持添加多个歌曲文件夹，不同硬盘中的歌曲可纳入同一个曲库。
- 歌曲文件保留在原目录，软件将各目录中的歌曲合并展示。
- 曲库页采用上下布局：上方为目录管理区，放置“添加文件夹”“刷新”、已添加目录及移除操作；下方展示曲库歌曲，复用已确认的歌曲列表样式。
- 使用“移除目录”操作停止收录该目录，解除它作为歌曲来源的关系；硬盘原文件保留。
- 移除目录后，歌曲若仍有其他已添加目录中的有效来源，则继续显示、保留收藏并允许点播；已无有效收录来源的歌曲按不可用规则处理，保留记录与收藏，默认隐藏。
- 首版不提供从软件中直接删除硬盘原文件的功能。
- 软件启动后自动在后台检查已添加目录，更新曲库。
- 软件运行期间新增或调整歌曲文件后，可通过曲库页的“刷新”手动更新列表。
- 刷新期间仍可浏览和点歌。

确认日期：2026-10-28。理由为允许分散存放的本地歌曲统一浏览，无需为加入曲库而搬动文件，明确曲库收录与硬盘文件管理的边界，并在更新目录内容时保留浏览和点歌能力。以上为设计确认，尚未实现或验收。

### 重复文件

- 不同目录中内容完全相同的 MV，在曲库中只显示一次，硬盘上的各份文件保留。
- 同一 MV 的多个来源中，只要仍有已收录且可访问的文件，歌曲就保持正常可用；移除一个目录或其中一份文件失效，不影响其他有效来源。
- 不同歌手或不同演唱版本按已确认的分组规则区分，不能仅凭歌名相同判定为重复文件；同版本的不同画质统一展示一个 MV 项，并采用最高可用画质。

确认日期：2026-10-28。理由为减少相同内容的重复展示，保持不同演唱版本可辨认，并避免移除单个目录或副本时误将仍可播放的歌曲判为不可用。以上为设计确认，尚未实现或验收。

### 不可用歌曲与隐藏选项

- 文件被移动、删除，或所在硬盘未连接时，先依据歌曲的全部已收录来源判断可用性；只有已无有效收录来源时，歌曲才视为不可用，仍保留记录和收藏状态。主动移除最后一个来源目录也按此规则处理。
- 不可用歌曲显示时，歌曲行灰显并标注“文件不可用”，暂时禁用预览及加入待播，仍可查看详情。
- 提供“隐藏不可用歌曲”选项；开启后，歌曲列表（含收藏页）不显示不可用歌曲，但内部继续保留歌曲记录和收藏关系，不因隐藏而取消收藏。
- 关闭隐藏选项后，可重新查看这些不可用歌曲；仍收录目录中的文件重新可访问，或先前移除的来源目录被重新添加后，刷新曲库即可恢复正常显示和操作，包括此前因不可用被隐藏的歌曲。
- “隐藏不可用歌曲”选项默认开启，用户可关闭以查看灰显的不可用歌曲。

确认日期：2026-10-28。理由为保留暂时不可用歌曲的资料与收藏，同时允许用户保持列表整洁。以上为设计确认，尚未实现或验收。

### 收藏页

- 首版保留一个收藏列表，不支持自建歌单。
- 收藏按时间倒序排列，后收藏的歌曲在上面；再次点击收藏按钮即可取消收藏。
- 收藏页不添加页内搜索，保持收藏列表浏览；需要查找歌曲时使用左侧的全局搜索入口。
- 默认隐藏不可用歌曲，但保留其收藏关系；关闭隐藏选项可重新查看。
- 主动移除来源目录同样保留收藏关系；只要其他已收录来源仍有效，歌曲照常可用。已因没有有效来源而隐藏的收藏，在重新添加来源目录并刷新曲库后恢复显示。

确认日期：2026-10-28。收藏排序与取消操作沿用用户明确给出的方案；查找方式按用户最新取舍，不添加收藏页内搜索，理由为保持页面简洁并复用全局搜索入口。不可用歌曲遵循已确认的隐藏规则。以上为设计确认，尚未实现或验收。
