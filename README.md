# Vesper

面向 Windows 的家庭 KTV 软件。目标是让选歌、排队和演唱自然连贯，同时认真打磨界面与操作反馈。

**当前阶段：产品设计与工程原型。main 已接入曲库与收藏、歌曲详情与联网资料检索、待播队列及恢复。本轮完善目录管理弹层、首页与创作页布局、创作页侧栏退场，实际界面效果待用户检查。首页推荐、创作编辑和完整演唱播放尚未接入；接续位置见下方项目记忆。**

## 已确定的方向

- Windows 桌面应用，采用 C#、.NET、WinUI 3 与 MVVM。
- 首版以本地曲库为基础，先完成电脑端点歌、排队与演唱；手机点歌及相关房间功能留到后续版本。
- 利用音乐文件和已有 MV 的命名、内嵌资料识别曲目，优先验证 B 站 MV 自动匹配；无匹配时采用流光与逐字歌词方向，不要求用户逐个检查 MV 版本。完整获取、播放和歌词匹配仍待实现，见 [歌曲详情调试](docs/歌曲详情调试.md)。
- 后续手机点歌保留局域网网页方案，无需安装专用 App。
- 主界面采用左侧导航、中央曲目推荐、右侧默认收起的待播队列。
- 卡拉 OK 演唱时视频全屏，选歌时返回主界面、声音不中断；目前取消同屏分屏及双显示器方案。
- 歌词优先评估复用 Lyricify 已开源的 .NET 歌词工具库。
- 保留共享低延迟、独占、兼容共享三种可切换 WASAPI 模式；实际支持范围和延迟需要设备验证。

具体按钮位置、预览行为与队列排序仍有讨论项；手机点歌及其多人权限留待后续。资料中的“已确认设计”不代表功能已实现。

## 讨论与交付方式

一次只讨论一个小问题或流程。明确确认后记录结论；设计、实现和验收分别标记。Casper 的日常开发和修复默认在 `main` 上进行，添加新功能时再新建分支；其他协作者使用个人任务分支和 PR，详见协作指南。

两位协作者和多台电脑各自使用独立克隆。开工前检查 Git 状态与分支，收工前提交并推送；不要用共享网盘同步同一个 Git 工作目录。

## 获取仓库

```powershell
git clone https://github.com/Casper-003/Vesper.git
```

使用 Visual Studio 打开 `Vesper.slnx`，将 `Vesper.App` 设为启动项目，选择 x64 与 Unpackaged 启动配置。命令行构建、当前可检查范围与尚未接入的功能见 [首轮调试](docs/首轮调试.md)。

请勿将个人曲库、录音、缓存、凭据或本机私有配置提交到仓库。
